# 🎛️ 手印認識の調整手順

> **ドキュメント種別:** 作業手順書
> **作成日:** 2026/10/11（B4.5）
> **関連:** [architecture/01_hand_input.md](architecture/01_hand_input.md)（仕組みの説明） / 仕様書 §5-2 / dev_log_B4.5

手印の判定に違和感が出たときに、どの値を見て、どう変えるかをまとめたもの。仕組みの詳細は 01_hand_input.md を参照。

---

## 1. 調整できる値

すべて `Assets/_MUDRA/Scripts/Input/HandTrackingService.cs` にある。コンストラクタ引数の3つは、既定値を `BattleInitializer` で上書きしていない。

| 値 | 場所 | 現在値 | 上げると | 下げると |
|---|---|---|---|---|
| 確定時間 `stableSeconds` | コンストラクタ引数 | 0.15秒 | 誤確定が減る／反応が遅くなる | 反応が速くなる／揺れた判定が確定しやすくなる |
| 静止閾値 `StillSpeedThreshold` | `private const` | 3.0（手のひら長/秒） | 動きながらでも確定する／組み替え途中の形が確定しやすくなる | しっかり止めないと確定しない |
| 速さの平滑化 `SpeedSmoothingSeconds` | `private const` | 0.1秒 | 速さが安定する／止めてから確定までが遅れる | 速さの反応が速い／保持中の揺れで「動いている」になりやすい |
| 合の保持時間 `UnionHoldSeconds` | `private const` | 0.5秒 | 合が途切れにくい／合のあと片手 Open に移るとき待たされる | Open への移行が速い／合の途中で Open が確定しやすくなる |
| 合の手首距離 `UnionWristDistanceRatio` | `private const` | 0.8（手のひら長に対する比） | 両手を少し離しても合になる | ぴったり合わせないと合にならない |
| 曲げ閾値 `bentThreshold` | コンストラクタ引数 | 45° | 人差し指〜小指が「伸び」と判定されやすい | 「曲げ」と判定されやすい |
| 親指の曲げ閾値 `thumbBentThreshold` | コンストラクタ引数 | 20° | 親指が「伸び」と判定されやすい（Palm→Open, Fist→Guard 寄り） | 「曲げ」と判定されやすい |
| ヒステリシス幅 `ThumbHysteresisDegrees` / `FingerHysteresisDegrees` | `private const` | 親指 3° / 他 5° | チラつきが減る／形を変えたときの切り替えが遅れる | 切り替えが速い／閾値付近でチラつく |

## 2. 症状から見る値

| 症状 | まず見る値 |
|---|---|
| 印を組み替える途中で、別の印（Cancel・Guard など）が出る | 静止閾値を下げる → 確定時間を上げる |
| 印を組んで止めても、なかなか確定しない | ログの「速さ」を見る。止めているのに 3.0 前後なら静止閾値を上げる。速さが低いのに遅いなら確定時間を下げる |
| 同じ形なのに印がチラつく（候補切替が頻発） | ヒステリシス幅を上げる。特定の指だけなら、その指の閾値 |
| Open と Palm、Fist と Guard を取り違える | 親指の曲げ閾値（親指の1本だけで区別しているため） |
| 合の途中で Open が出る | 合の保持時間を上げる |
| 合のあと片手の Open がすぐ出ない | 合の保持時間を下げる |
| 両手を合わせても合にならない（2本は見えている） | 合の手首距離を上げる |
| 両手を合わせても1本しか映らない | 値では直らない（§5） |

## 3. ログの出し方と読み方

1. InGame の `BattleSystem` にある `HandSignPresenter` で、**`Log Hand Sign Judgement` をオン**にする（Play 中に変えても反映されない。Play 前に設定する）
2. Play して印を組む。Console を `[HandSign]` で絞り込む
3. 終わったらオフに戻す（シーンに保存される値なので、戻し忘れるとログが出続ける）

エディタと Development Build だけで動く。リリースビルドにはログのコード自体が入らない。

| ログ | 意味 | 見るところ |
|---|---|---|
| `確定 X（積算A秒・実時間B秒・速さ C）` | X が確定した | B が体感の反応時間。A は確定時間とほぼ同じ。B − A が「静止待ち」にかかった時間 |
| `候補切替 X → Y（Xは積算A秒・実時間B秒で途切れ・速さ C）` | X が確定する前に Y に変わった | 組み替え中に出るのは正常。止めているのに頻発するならチラつき。A が確定時間に近い候補は、あと少しで誤確定していた |
| `合の保持 開始` / `終了（時間切れ）` / `終了（他の印: X）` | 合の保持の出入り | 合の途中で「時間切れ」が出るなら保持時間が短い |

### 判断の目安（B4.5 の実測）

| 状況 | 速さ（平滑化後） |
|---|---|
| 印を組んで止めている | 平均 約0.7 |
| 印を組み替えている最中 | 平均 2〜8、最大 16〜39 |
| 組み替え途中で一瞬成立した Cancel | 3.6〜4.9 |

静止閾値 3.0 は「止めている」と「組み替え中の中間の形」の間に置いた値。

| 状況 | 実測 |
|---|---|
| 描画 FPS | 約170（術の発動直後などで130台まで下がる） |
| 推論回数 | 手があるとき 25〜35回/秒 |
| 合わせて止めたときの検出 | 1本 68〜89%、2本 11%前後。2本の検出は1秒に2〜3回（間隔 平均0.4秒前後） |

合の保持 0.5秒は、2本検出の間隔（約0.4秒）を少し上回るように決めた。

## 4. MediaPipe の設定ウィンドウ

InGame の右下のカメラ映像の下にあるボタンで開く。

- **開いている間は推論が止まり、手印も認識されない**
- 変えた値は実行中だけ有効。残したい値は、Play を止めてから `Solution` の `HandLandmarkerRunner` に設定する
- 既定値（Delegate CPU / Image Read Mode CPU Async / Running Mode LIVE_STREAM / Num Hands 2 / 各 Confidence 0.5）は B4.5 で確認済み。Windows では GPU を選べない。Num Hands は両手印に必要なので 2 から減らさない
- 各 Confidence を下げると手の見逃しは減るが、手でないものを手と誤検出しやすくなる。合が1本になる問題には効かない

関節の表示（点の大きさ・色）は `Main Canvas/Body/Annotatable Screen/Annotation Layer` 配下の `Multi HandLandmarkList Annotation` で変える。線の太さ `Connection Width` は上限の1になっていて、これ以上太くできない。

## 5. 値では直らないこと

- **合わせた両手が1本の手として検出される。** 横向きで重なった手のひらは MediaPipe の苦手な条件で、重なった2つの検出候補が1つにまとめられる。合の保持は「一度は2本が見えた」ことが前提なので、最初から1本しか見えないと合にならない。手を少し手前に傾けるなど、カメラから両手が見えやすい組み方にすると改善する可能性はある（未検証）。根本的には、合の手形を見直すか、別の検出方法が必要になる
- **手の左右（handedness）を取り違える。** 両手印の判定は左右の振り分けに頼っている。取り違えると両手印にならない
