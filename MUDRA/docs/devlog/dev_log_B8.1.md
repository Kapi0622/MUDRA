## 1. 概要

| 項目 | 内容 |
|---|---|
| **出発点** | `SpellData` に図鑑用の `description` / `icon` の欄はあったが11術すべて空。`EnemyData` には説明文の欄が無い。術の情報はポーズ画面の一覧（印の並び）にしかなかった |
| **ゴール** | プレイヤーの認知コストを下げ、要素に愛着を持ってもらう。「ふと眺めたくなる」読み物としての図鑑 |
| **結果** | ステージ選択から開く図鑑（タブ「術／妖」・一覧・詳細）。術11種は最初から、妖15体はステージのクリアで解放。説明文26本、術アイコン11枚、和紙の台紙 |
| **変えなかったもの** | セーブの形（クリア記録をそのまま使う）、ゲームの数値、InGame 側 |
| **進め方** | 事前に質問（入口・解放・数値の見せ方・素材・画面の形・仕掛け）→ データ → 文章とプロンプト → コード → シーン構築（MCP）→ 素材の取り込み → 仕上げ。各ステップ「提案 → 承認 → 実装 → 確認」 |

### 規模
- 自前コード: **134 ファイル・約 14,900 行**
- 新規クラス: `CodexPresenter` / `StageRecordFormat` / `CodexView`（＋`CodexEntry` / `CodexTab`）/ `CodexListItemView` / `CodexImagePlate`
- 変更クラス: `EnemyData`（`description`）/ `StageSelectView` / `ScreenPresenter` / `AppInitializer`
- 新規アセット: `Sprites/SpellIcon/`（`T_UI_SpellIcon_*` 11枚・`T_UI_IconPlate`）
- 変更アセット: `App.unity`（`CodexScreen`・図鑑ボタン・`CodexPresenter`）、術 SO 11本（`icon` / `description`）、敵 SO 15本（`description`）

## 2. 決めた方針（論点と結論）

| # | 論点 | 結論 | 補足 |
|---|---|---|---|
| 1 | 入口 | **ステージ選択から**（ボタン＋`C`） | 挑む前に弱点を確かめられる。タイトル・ポーズからは開かない |
| 2 | 解放 | 術は最初から全部。妖は**出てくるステージのどれかをクリアしたら** | `ProgressModel.FindRecord` をそのまま使えるのでセーブを変えずに済む（ユーザー提案）。未解放は黒い影＋「？？？」＋出現ステージ名 |
| 3 | 木人 | **載せない** | `_allStages` から敵を集めるので、`SD_Tutorial` の木人は自然に外れる |
| 4 | 数値の見せ方 | **★5段階にぼかす** | 攻略本でなく読み物として。威力は `basePower`、体力は `maxHp` を閾値で段階に。攻撃は名前と「（大技）」のみ。回復だけの術は威力の★を出さない |
| 5 | ★の閾値 | 威力 60/85/110/140、体力 300/500/700/1600 | `balance_sheet.md` の散らばりから。雑魚は体力★1〜3、ボスは★4〜5に収まる |
| 6 | 画面の形 | タブ＋左に一覧＋右に詳細 | 全体量と未解放の数が一目で分かる |
| 7 | 仕掛け | 妖の詳細に**出現ステージの記録**（ステージ名・ベストランク・時間） | 既存の記録を使うので保存の追加なし。ゆらゆら動く絵・相互リンク・NEW 印は見送り |
| 8 | 説明文 | Claude が下書き → ユーザーが直す。2〜3文、**最後の一文は遊び方のヒント**、数値は書かない | 図鑑を読むだけで戦い方が分かるようにする |
| 9 | 表示用の型 | 術と妖で**1つの `CodexEntry`** | 計画では2つに分ける予定だったが、View が中身の意味を知らずに並べるだけにするため1つにした |
| 10 | 術アイコン | 白地に黒い墨で生成。**画像は触らず、円い和紙の台紙に載せる** | 当初は「白い墨に変換して属性色で染める」案だったが、ユーザーの選択で台紙方式に |
| 11 | 白地が残ったアイコン（4枚） | 画像は触らず、和紙の平均の色（`_imageTint`）を掛けて白をなじませる | 白地を抜いた画像に差し替えれば色掛けは不要 |

## 4. つまずいた点

| # | 内容 | 対処 |
|---|---|---|
| 1 | 図鑑を `Esc` で閉じると、同じフレームでステージ選択も `Esc` を拾ってタイトルへ戻る | `StageSelectView.Resume` と `CodexView.Show` で、そのフレームはキー入力を読まない |
| 2 | 白を α0.04 で重ねた枠が、画面では明るい灰色になった | Linear 色空間では薄い白でも明るく出る。枠は黒の半透明（0.45）で暗くする方式に、暗幕は 0.97 に |
| 3 | MCP のスクリーンショットが半透明の重なりを正しく写さない（カメラ映像が画面より手前に写る） | 配置の確認にだけ使い、色味は Game ビューでユーザーが確認 |
| 4 | アイコンが Sprite Mode = Multiple で取り込まれ、飛沫ごとに自動で切り分けられていた（業火は8つ） | Single に戻した。`spell_icon_prompts.md` §5 に注記 |
| 5 | 11枚のうち4枚は白地のまま、7枚は透過済みと、状態がそろっていなかった | 台紙方式＋`_imageTint` で、画像を触らずに見た目をそろえた |
| 6 | 和紙が取り込み前（`.meta` 無し）で `FindAssets` に出てこなかった | ファイルを直接探して見つけ、黒地を透明化してから取り込み |
| 7 | MCP の `execute_code` は C# 6（CodeDom）で、`Object` が曖昧・`?.` が Unity の null 判定で例外になる | `UnityEngine.Object` と明示、null 判定はラムダで |

## 5. 技術的負債・保留事項

| 項目 | 内容 |
|---|---|
| 未解放表示の確認 | ユーザーのセーブが全クリア済みのため、「？？？」は画面で未確認 |
| 白地の残るアイコン4枚 | 双刃・火炎弾・光輪・水爪。白地を抜いた画像に差し替えたら `_imageTint` を白にしてよい |
| 一覧のスクロール | 選択位置から単純に正規化位置を計算している。項目が大きく増えたら、見えている範囲に入れる方式に |
| 解放の通知 | 新しく解放された妖を知らせる仕組み（NEW 印・リザルトでの告知）は無い |
| `TempHandTrackingRunner` の NRE | B6.5 から持ち越し |
