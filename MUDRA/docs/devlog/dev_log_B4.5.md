## 3. 設計判断の記録

### 3-1. 計測で「FPS低下が原因」の仮説を捨てた

最初の仮説は「描画フレーム数で確定を数えているので、FPSが落ちると確定が遅くなる」だった。60FPS 固定を入れる案も出していた。実測すると、FPS は普段 約170、術の発動直後などでも130台で、100を切ることはほぼなかった。むしろ FPS が高いほど 36フレームは短くなる（約160FPSで0.23秒）。60FPS に固定すると確定が0.6秒になり、遅くなるだけだったので取りやめた。

一方で、推論は手があるとき 25〜35回/秒しか回っておらず、判定は同じ推論結果を1回あたり約5回数えていた。確定時間の長さそのものより、「短くすると組み替え途中の形が確定する」ことが問題の中心だと分かった。

### 3-2. 確定はフレーム数ではなく秒で数える

FPS に左右されないよう、`Tick(deltaTime)` で経過時間を積算する。描画FPSは環境（他のアプリの負荷など）で100前後まで変わるため、フレーム数では確定時間が安定しない。

### 3-3. ヒステリシスは左右の手ごとに持つ

閾値付近で角度が揺れると、曲げ判定が反転して候補が切り替わり、確定までの積算がやり直しになる。前回「曲がっている」なら閾値を下げ、「伸びている」なら上げる。2手検出時は MediaPipe が返す手の順番が入れ替わることがあるので、配列の添字ではなく handedness（左・右・不明）で区分した。見えなくなった区分の履歴はその Tick の末尾で捨てる。

### 3-4. 「止まっている間だけ数える」で、短い確定時間と誤確定防止を両立

確定時間を短くすると、印の組み替え途中の中間の形（例: Cancel → Release の途中の Cancel、0.15秒続いた例があった）が確定してしまう。中間の形は手が動いている最中に現れるので、手の速さが閾値未満のときだけ時間を進めるようにした。

- 速さは手首と5本の指先の移動量を手のひら長で割る（カメラとの距離に左右されない）
- 推論1回ごとの値は保持中でも最大2.5程度まで跳ねるので、指数移動平均（時定数0.1秒）でならす
- 速さは新しい推論結果が届いたとき（`ResultVersion` の変化）だけ更新する。同じ結果を何度も比べると速さが0に見えるため
- 新しく現れた手は前回の位置がないので「動いている」扱いから始める。手を上げてきた直後に止まる前に確定するのを防ぐ

閾値3.0は実測（保持中の平均 約0.7、組み替え中の平均 2〜8・最大 16〜39、途中で一瞬成立した Cancel 3.6〜4.9）から決めた。確定時間は 0.23秒 → 0.15秒 に短縮した。

### 3-5. 合の保持は Open に限った対処にした

合わせて止めた手は、1本の「開いた手」として検出されがちだった（1本 68〜89%、2本 11%前後）。横向きで重なった手のひらは MediaPipe の苦手な条件で、重なった2つの検出候補が1つにまとめられる。そのため、止めた状態で Open が確定してしまっていた。

Union と判定したあと0.5秒は、1本の Open を Union とみなす。Open 以外の印が来たらすぐ保持をやめ、合のあとに次の印へ移るときは待たせない。合わせた手が別の形（Palm など）に見える例はまだ出ていないので、Open に限った。例外が出たら見直す。保持中は「新しく現れた手」による速さの引き上げも行わない。2本目の出入りや左右判定の入れ替わりのたびに「動いている」扱いになり、Union の確定時間が進まなくなるため。

### 3-6. 調整用ログは消さずに切り替え式で残した

閾値は今後も定期的に調整する予定なので、判定の経過ログ（候補切替・確定・合の保持）は残した。`HandSignPresenter` のチェックでオンにし、既定はオフ。1秒ごとに出ていた FPS・推論回数・速さの平均のログは、調整の判断には「確定」「候補切替」に付く速さで足りるので削除した。

## 6. 技術的負債・保留事項

| 負債 | 対処方針 |
|------|----------|
| **合わせた両手が1本しか検出されないことが多い** | MediaPipe の苦手な条件で、設定値では直らない。見送り。合の手形を見直すか、検出方法を変えるときに再検討 |
| 合の保持は Open に限った対処 | 合わせた手が別の形に見える例が出たら見直す |
| 閾値（確定時間・静止閾値・合の保持時間）は出発点の値 | 定期的に調整する。手順は `docs/hand_sign_tuning.md`。B6 のキャリブレーションで ScriptableObject 化を検討 |
| `TempHandTrackingRunner` / `HandTrackingActiveTest` はコンポーネントを無効にしただけ | スクリプトを消すかは未定 |
| 線の太さ `Connection Width` は上限の1 | もっと太くするなら、映像の縮小を Scale ではなく RectTransform のサイズで行う。推論処理が実行時にサイズを設定するので、コード側の対応が要る |

## 8. B5への引継ぎ

- B5 でポーズを作るとき、`HandSignPresenter.Update()` は `Time.deltaTime` で判定を進めている。`Time.timeScale = 0` にすると判定も止まる（ポーズ中に印が確定しない）。ポーズ中も印で操作したい場合は `unscaledDeltaTime` を渡すなどの検討が要る
- MediaPipe の設定ウィンドウは開いている間推論を止める。B5 のポーズ機能と役割が重なるので、リリース時に `Footer` を残すかは B5〜B9 で決める
