## 1. 概要

| 項目 | 内容 |
|---|---|
| **出発点** | 記録と設定は `persistentDataPath/save.json` 1ファイル（B5）。リセットの手段は無く、消すにはエクスプローラーでファイルを削除するしかなかった。**エディタとビルド版が同じファイルを共有**しており、テストプレイの記録（全クリア済み・ベストランク）がビルド版にそのまま引き継がれていた |

| **進め方** | 現状調査 → 質問（リセットの方式・消す範囲・手動の手段）→ 計画承認 → 実装 |

## 2. 決めた方針（論点と結論）

| # | 論点 | 結論 | 補足 |
|---|---|---|---|
| 1 | 「ビルドすると必ずリセット」の形 | **新ビルドの初回起動で初期化** | ビルドごとに Unity が振る `Application.buildGUID` を保存し、起動時に比べる。どの PC で起動しても効き、同じビルドの2回目以降は記録が残る。「ビルドの瞬間に開発 PC のファイルを消す」案は、その後エディタで遊ぶとまた引き継がれるので不採用 |
| 2 | 消す範囲 | **記録も設定も全部** | 配布したときの状態と完全に同じにするため。音量・フルスクリーンなども既定値に戻る |
| 3 | 判定の置き場所 | **`JsonFileSaveStorage`（Persistence 層）だけ** | `buildGUID` は Unity API なので Model に入れない。ID 違いは「ファイルが無い」と同じく null を返すだけにし、`ProgressModel` は今の「null なら初期状態」の経路をそのまま使う |
| 4 | エディタでの扱い | **ID を比べずに読み、保存時は空の ID を書く** | エディタで遊んだ後のファイルは、ビルド版から見ると ID 違いになる。結果として「エディタとビルドでファイルを分ける」案と同じく、エディタの記録がビルド版に混ざらない |
| 5 | ID 違いのファイル | **消さずに null を返す** | 最初の保存で上書きされる。保存が起きなければ次回も初期状態になるだけで矛盾しない |
| 6 | `version` | **上げない** | 古いファイルは `buildId` が null で読まれ、ビルド版では ID 違い＝初期化になる。望む挙動と一致する |
| 7 | 手動の手段 | **Editor メニュー**（ゲーム内には入れない） | 再生中はメニューを無効にする。`ProgressModel` がメモリの値を次の保存で書き戻し、消しても元に戻るため |

## 4. 確認手順（ユーザー側）

1. コンパイルエラーが無いこと
2. エディタで再生して音量を変えると、`save.json` に `"buildId"` が入る（エディタでは空の想定）
3. ビルドして起動すると、記録と音量が初期値。Player.log に「[Save] 新しいビルドのため初期状態で始めます」
4. ビルド版でステージをクリアして再起動すると、記録が残っている
5. 再ビルドして起動すると、初期状態に戻る
6. エディタ停止中に「MUDRA/Reset Save Data」でファイルが消える。再生中はメニューがグレー

## 5. 技術的負債・保留事項

| 項目 | 内容 |
|---|---|
| エディタの `buildGUID` | 空文字の想定。空でなくても判定は `#if !UNITY_EDITOR` 側だけなので挙動は変わらない（保存される値が変わるだけ）。手順2で確認する |
| 配布後のアップデート | ビルドが変わるたびに記録が消えるので、**配布版を更新するときに記録を引き継ぎたくなったら、この判定を外すか、開発ビルドだけに絞る**（`DEVELOPMENT_BUILD`）必要がある |
| `companyName` | `DefaultCompany` のまま。変えると保存先のフォルダが変わり、記録とレジストリの解像度設定が引き継がれなくなる |
| Unity 本体の保存 | 解像度などはレジストリ（`HKCU\Software\DefaultCompany\MUDRA`）に Unity が保存しており、このリセットの対象外 |
| CLAUDE.md の規模 | 「129ファイル」「Editor 2本」の記述が古い |
| `TempHandTrackingRunner` の NRE | B6.5 から持ち越し |
